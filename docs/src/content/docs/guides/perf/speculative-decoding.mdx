import { Tabs, TabItem } from '@astrojs/starlight/components';

Speculative decoding drafts several tokens per step using a separate assistant or the model's built-in prediction head. The target model verifies the drafts in parallel before emitting accepted tokens. Configure it through the MTP (Multi-Token Prediction) API.

:::caution
Speculative decoding requires [paged attention](/guides/perf/paged-attention/), which is enabled by default on CUDA.
:::

<Tabs>
<TabItem label="CLI">

```bash
mistralrs run -m google/gemma-4-E4B-it --quant 8 \
  --mtp-model google/gemma-4-E4B-it-assistant \
  --mtp-n-predict 6
```

`--mtp-model` accepts a Hugging Face id or a local path. The same flags work with `mistralrs serve`. See [run](/reference/cli/run/) and [serve](/reference/cli/serve/) flag references.

</TabItem>
<TabItem label="Python">

```python
from mistralrs import Runner, Which

runner = Runner(
    which=Which.MultimodalPlain(model_id="google/gemma-4-E4B-it"),
    in_situ_quant="8",
    mtp_model="google/gemma-4-E4B-it-assistant",
    mtp_n_predict=6,
)
```

Gemma 4 loads via `Which.MultimodalPlain` and uses a separate assistant checkpoint.

</TabItem>
<TabItem label="Rust">

```rust
let model = mistralrs::ModelBuilder::new("google/gemma-4-E4B-it")
    .with_mtp_model("google/gemma-4-E4B-it-assistant", Some(6))
    .build()
    .await?;
```

You can also pass `MtpConfig::new("google/gemma-4-E4B-it-assistant", Some(6))` to `with_mtp_config`. Use `MtpConfig::builtin(None)` for a built-in head with automatic draft depth. These methods are available on the text, multimodal, and auto-detecting model builders.

</TabItem>
</Tabs>

`--mtp-n-predict N` fixes draft depth. Leave it unset to let the engine adapt to acceptance, memory, and serving load. Benchmark with representative prompts; extra drafting work is useful only when the target accepts enough tokens.

## Supported models

| Mode | Target models | Assistant model | Status |
|---|---|---|---|
| MTP | Gemma 4 | Gemma 4 assistant checkpoints (`--mtp-model`) | Supported with paged attention |
| MTP | Qwen3.5, Qwen3.8 | Built into the checkpoint (`--mtp`) | Supported with paged attention |
| MTP | Qwen3.8-Flash-Next | Built into the checkpoint (`--mtp`) | Safetensors/UQFF with paged attention |
| DFlash / DFlash 2 | Qwen3.5, Qwen3.8 | DFlash draft checkpoints (`--mtp-model`) | Supported with paged attention |

## Qwen3.5 / Qwen3.8

Qwen3.5 and Qwen3.8 checkpoints ship a multi-token prediction head (`mtp.*` weights) sharing the target's embeddings and `lm_head`. Pass `--mtp` to load it; no separate assistant model is needed:

```bash
mistralrs serve -m Qwen/Qwen3.8-27B --quant 4 --mtp
```

Safetensors and UQFF checkpoints must contain the `mtp.*` weights; GGUF loading does not support built-in MTP.

Multi-token verification can use different quantized matrix and recurrent kernels from ordinary decoding. Log probabilities and greedy token choices can differ, so token-for-token equivalence is not guaranteed.

Built-in Qwen MTP recomputes cached prompt prefixes, which can increase time to first token for repeated prompts. This restriction does not apply to DFlash.

Qwen3.8-Flash-Next uses the same built-in-head flags:

```bash
mistralrs serve -m Qwen/Qwen3.8-Flash-Next --isq q4k --mtp
```

Flash-Next supports only its built-in head. External assistants and DFlash are unsupported. See [model-family notes](/guides/models/model-family-notes/#qwen38-flash-next) for memory requirements.

## DFlash and DFlash 2 (Qwen3.5 / Qwen3.8)

Pass a compatible DFlash or DFlash 2 checkpoint to `--mtp-model`; the format is detected automatically:

```bash
mistralrs serve -m Qwen/Qwen3.8-27B --quant 4 \
  --mtp-model incoai/Qwen3.8-27B-DFlash2
```

`--mtp-draft-sampling` defaults to `auto`. A DFlash 2 checkpoint uses probabilistic drafting when
its CUDA candidate selector is supported, while DFlash 1 and unsupported devices use greedy
drafting. Pass `--mtp-draft-sampling greedy` to force greedy drafting. Passing `probabilistic`
requires a supported DFlash 2 selector and fails during loading when that path is unavailable.

Leave draft depth automatic initially. Use `--mtp-n-predict` for a fixed depth when comparing workloads. The draft model follows the target's in-situ quantization; `MISTRALRS_DFLASH_ISQ` overrides it (for example `q6k` or `none`).

Acceptance varies with content, so compare total throughput and latency on your own math, code, or conversational prompts.

## Gemma 4

Use the assistant checkpoint matching the target model, as in the examples above. `--mtp-model` also accepts a local checkout. Incompatible vocabulary or hidden sizes fail at load.

## Notes

Throughput gain depends on how many proposed tokens the target accepts and on the cost of the target verification pass.

MTP supports batched generation and constrained decoding.

MTP is configured at launch time only (CLI flags, `Runner(...)`, or the model builder). There is no per-request HTTP field to toggle it; load the server with the assistant attached and every request uses it.
