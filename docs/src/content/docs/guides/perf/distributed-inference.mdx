Choose a distribution mode based on your hardware:

| Mode | Use when |
|---|---|
| NCCL tensor parallelism | Similar CUDA GPUs on one or more machines. |
| Layer mapping | Uneven devices, unavailable NCCL, or explicit layer placement. |
| Ring backend | You specifically need the `ring` transport instead of NCCL. |

## Selection flow

Multiple visible CUDA GPUs use NCCL when compiled in, otherwise layer mapping. `MISTRALRS_NO_NCCL=1` disables NCCL. Manual layer mapping overrides automatic placement. Check startup logs for the selected layout.

Use `MISTRALRS_MN_*` for multi-node NCCL, or `RING_CONFIG` for ring. A binary with both features needs `MISTRALRS_NO_NCCL=1` to select ring.

## Single machine, multiple GPUs

### Build requirements

Linux CUDA installs enable `nccl` when the installer or wheel builder finds `libnccl`.

Manual Linux CUDA build with NCCL:

```bash
cargo install mistralrs-cli --features "cuda nccl flash-attn cudnn"
```

If NCCL is not installed, omit `nccl`. For installer source builds, pass `--no-nccl` to skip it; see [installer options](/reference/installer/). To disable NCCL at runtime without rebuilding:

```bash
MISTRALRS_NO_NCCL=1 mistralrs serve -m Qwen/Qwen3-32B --quant 4
```

### Select GPUs

Use `CUDA_VISIBLE_DEVICES` to restrict the GPU set before mistral.rs starts:

```bash
CUDA_VISIBLE_DEVICES=0,1 mistralrs serve -m Qwen/Qwen3-32B --quant 4
```

The ordinals in `--device-layers` are the visible ordinals after `CUDA_VISIBLE_DEVICES` is applied.

NCCL tensor parallelism uses all visible CUDA GPUs. The tensor-parallel size must be compatible with the model:

- Attention heads must divide evenly across GPUs.
- KV heads must either divide evenly across GPUs or be replicated evenly when there are fewer KV heads than GPUs.

If the visible GPU count is incompatible, mistral.rs errors instead of selecting a smaller subset. Use `CUDA_VISIBLE_DEVICES` to choose a compatible subset.

### Layer mapping (CUDA P2P)

Automatic mapping assigns contiguous layers using available device memory and the [memory budget](/guides/perf/paged-attention/#memory-budget). Override it when uneven GPUs or transfer costs need a different split:

<Tabs>
<TabItem label="CLI">

`-n`/`--device-layers` takes the format `ORD:NUM;...`:

```bash
mistralrs serve -n "0:32;1:32" -m <model>

# Uneven split
mistralrs serve -n "0:44;1:20" -m Qwen/Qwen3-32B --quant 4
```

</TabItem>
<TabItem label="Python">

`num_device_layers` takes a list of `"ORD:NUM"` strings:

```python
from mistralrs import Runner, Which

runner = Runner(
    which=Which.Plain(model_id="Qwen/Qwen3-32B"),
    num_device_layers=["0:32", "1:32"],
)
```

</TabItem>
</Tabs>

For per-layer or per-tensor placement, use the [topology guide](/guides/perf/topology/).

### Performance notes

Layer mapping uses CUDA peer access where available; CPU-staged transfers log a warning and can be slower. Automatic placement accounts for memory, not PCIe/NVLink topology or GPU speed. Use explicit layer counts when those differences matter.

On discrete GPUs, automatic placement can spill weights to CPU; this disables paging. An explicit paged memory goal fails instead. Apple Silicon has one shared memory pool, so CPU placement does not add capacity. See [memory budgets](/guides/perf/paged-attention/#memory-budget).

## Multi-node NCCL

Use the same CUDA+NCCL build, model, dtype, quantization, and runtime arguments on every node. Each node must contribute the same number of visible GPUs. Global world size is that count multiplied by the number of nodes and must satisfy the model's head-divisibility rules.

Do not set `MISTRALRS_NO_NCCL` or `RING_CONFIG`. The [environment reference](/reference/environment-variables/) documents all `MISTRALRS_MN_*` settings.

Two nodes, four GPUs per node:

Head node:

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 \
MISTRALRS_MN_GLOBAL_WORLD_SIZE=8 \
MISTRALRS_MN_LOCAL_WORLD_SIZE=4 \
MISTRALRS_MN_HEAD_NUM_WORKERS=1 \
MISTRALRS_MN_HEAD_PORT=9000 \
mistralrs serve -m Qwen/Qwen3-32B --quant 4
```

Worker node:

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 \
MISTRALRS_MN_GLOBAL_WORLD_SIZE=8 \
MISTRALRS_MN_LOCAL_WORLD_SIZE=4 \
MISTRALRS_MN_WORKER_SERVER_ADDR=10.0.0.1:9000 \
MISTRALRS_MN_WORKER_ID=0 \
mistralrs serve -m Qwen/Qwen3-32B --quant 4
```

Send requests to the head node; its startup port must be reachable from every worker.

:::caution
On multi-interface machines, NCCL may pick the wrong network interface between nodes and hang at startup. Set `NCCL_SOCKET_IFNAME` (and other NCCL networking variables as needed) in the shell before launching.
:::

## Ring backend

Ring requires the `ring` feature. Prefer multi-node NCCL for CUDA tensor parallelism unless you specifically need ring:

```bash
cargo install mistralrs-cli --features "cuda flash-attn ring"
```

If the binary is also built with `nccl`, set `MISTRALRS_NO_NCCL=1` when launching so the ring backend is selected.

Set `RING_CONFIG` to a JSON file on each participant with its own rank and neighbor addresses:

```json
{
  "master_ip": "10.0.0.1",
  "master_port": 9000,
  "port": 9001,
  "right_port": 9002,
  "right_ip": "10.0.0.2",
  "rank": 0,
  "world_size": 2
}
```

`world_size` must be a power of 2 (the ring backend rejects other values at startup). Non-master ranks (`rank != 0`) must specify `master_ip`. The master rank (`rank = 0`) is reachable via `master_ip`.
