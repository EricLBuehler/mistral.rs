Paged attention shares a fixed KV cache budget across concurrent requests. It is enabled by default on supported CUDA and Metal models. Start with automatic sizing; set a budget only when you need a specific capacity.

<Tabs>
<TabItem label="CLI">

```bash
mistralrs serve -m Qwen/Qwen3-4B
```

Use `--kv-cache 8GiB` for a shared byte budget, `--kv-cache 65536tokens` for token capacity, or `--gpu-memory-utilization 0.9` for a total GPU memory target. `--paged-attn off` disables paging; `auto` is the default.

</TabItem>
<TabItem label="Python">

```python
from mistralrs import Runner, Which

runner = Runner(which=Which.Plain(model_id="Qwen/Qwen3-4B"))
```

Set `memory_goal="8GiB"`, `memory_goal="65536tokens"`, or `memory_goal=0.9` for the corresponding budget. `no_paged_attn=True` disables paging. [Full example](/examples/python/paged-attention/).

</TabItem>
<TabItem label="Rust">

```rust
use mistralrs::ModelBuilder;

let model = ModelBuilder::new("Qwen/Qwen3-4B").build().await?;
```

Use `.with_memory_goal(MemoryGoal::KvBytes(8 * 1024 * 1024 * 1024))`, `MemoryGoal::KvTokens(65536)`, or `MemoryGoal::Utilization(0.9)`. Import `mistralrs::MemoryGoal`. `.without_paged_attn()` disables paging. [Full example](/examples/rust/advanced/paged-attn/).

</TabItem>
</Tabs>

CPU and unsupported model loaders use the standard cache. Explicit memory budgets require supported paging and fail if they cannot fit.

## Memory budget

| Setting | What it controls |
|---|---|
| Default (`Auto`) | Places weights and reserves workspace before sizing the KV pool, with system headroom. |
| KV bytes or tokens | Shared cache capacity across requests and all of the model's devices. |
| GPU memory utilization | Total budget for weights, workspace, and KV cache, subject to available memory. |
| `--max-model-len` | Each request's prompt plus output limit. |
| `--max-seqs` | Concurrent running requests. |

Choose either a KV capacity or a utilization target. A 65,536-token shared cache does not give every request that capacity. If requests are frequently preempted, lower concurrency or increase cache capacity. See [throughput tuning](/guides/perf/throughput-tuning/).

### Automatic sizing

Automatic sizing leaves system headroom and respects current device availability. Other applications, larger batches, and more concurrent requests can reduce usable cache capacity. On Metal, the device's recommended working-set limit also applies. Leave overrides unset unless measurements show a need to change them.

### Explicit capacity and utilization

Byte budgets include cache allocation overhead; usable token capacity can be lower than a bytes-per-token estimate. Token budgets round up to whole blocks. Explicit capacities fail rather than silently shrink.

### Multiple models

[Multi-model serving](/guides/serve/multiple-models/) divides the initial memory budget between models according to serving concurrency. Each model's explicit KV capacity must fit its share. Conflicting utilization targets are rejected. Models with paging disabled do not have bounded paged-cache quotas.

### Cache and scheduler controls

| Option | Default | Use |
|---|---|---|
| `--pa-block-size` | 32 | Cache block size; supported values are 8, 16, and 32. |
| `--pa-cache-type` | `auto` | Use `f8e4m3` to halve KV storage relative to BF16. Separate from model-weight quantization; unavailable for MLA caches. |

Leave block size at its default unless benchmarking. Prompt chunking and decode fairness are covered in [mixed prefill and decode](/guides/perf/throughput-tuning/#mixed-prefill-and-decode); all flags are in the [serve reference](/reference/cli/serve/).

## How it works

Requests allocate cache blocks as they grow and share blocks for matching prefixes. Finished requests release their blocks for reuse. See [inference runtime internals](/developer/inference-runtime/) for memory planning and kernel selection.

## Metal prefill and decode

The default Metal layout supports paged prefill, decode, and prefix sharing. For comparison with the legacy layout, set `MISTRALRS_METAL_PAGED_LAYOUT=legacy` before loading the model. This keeps paging enabled; `--paged-attn off` disables it entirely.

## CUDA fast paths

CUDA chooses compatible paged prefill and decode kernels automatically. To compare against the generic paged decode path, set `MISTRALRS_FLASHINFER_DECODE=0` before loading. This is a debugging option, not a required tuning step.

## Flash attention vs FlashInfer

Paged attention and flash attention can be enabled together. FlashInfer paged decode ships with `cuda`; standard and fallback flash-attention paths use the `flash-attn` or `flash-attn-v3` build features. See [Cargo features](/reference/cargo-features/) for hardware requirements.

## CUDA graphs

CUDA decode graphs reduce CPU launch overhead and are enabled by default on supported paged models. They do not apply to prompt prefill. Disable them for a comparison with `MISTRALRS_CUDA_GRAPHS=0`.

### Replay preconditions

Unsupported models, request shapes, or memory conditions use normal CUDA execution. Capture failures also fall back; inspect the warning log when diagnosing a slowdown. [Developer details](/developer/inference-runtime/#cuda-graphs).

### When graphs help

Measure steady-state decode latency after warmup. Small models and short decode steps often benefit most; new batch or context shapes may need another capture.

## Upgrading from 0.9.4

Paging is now automatic on supported Metal models. Use the disable options above to retain the standard cache.

### CLI and TOML

Replace `--pa-context-len N` with `--kv-cache Ntokens`, `--pa-memory-mb N` with a byte budget, and `--pa-memory-fraction F` with `--gpu-memory-utilization F`. The old memory amount was in MiB; the new budget covers all devices. TOML uses `kv_cache` or `gpu_memory_utilization` under `[paged_attn]`.

Remove old placement hints `--max-seq-len` and `--max-batch-size`. Use `--max-model-len` for request limits and `--max-seqs` for concurrency. `run` defaults to 1 sequence; `serve` defaults to 32.

### Python

Replace `pa_ctxt_len`, `pa_gpu_mem`, and `pa_gpu_mem_usage` with `memory_goal`. Remove `auto_map_params` and `multimodal_auto_map_params`; placement uses memory and serving limits. Set `max_seqs=16` explicitly to preserve the old Python default; the current default is 32.

### Rust

Replace `MemoryGpuConfig` with `MemoryGoal`: `ContextSize` becomes `KvTokens`, `MbAmount` becomes `KvBytes`, and `Utilization` keeps its meaning. Replace `.with_gpu_memory(...)` with `.with_memory_goal(...)`. The default is now `Auto`, not 4,096 tokens.

Omit `DeviceMapSetting::Auto` for automatic placement. Manual `.with_device_mapping(...)` takes `DeviceMapMetadata` directly; see [layer mapping](/guides/perf/distributed-inference/#layer-mapping-cuda-p2p).
