Embedding models return vectors through `/v1/embeddings` or the native SDKs. Use the same model and preprocessing for indexed documents and later queries.

## Loading an embedding model

```bash
mistralrs serve -m google/embeddinggemma-300m
```

EmbeddingGemma-300M returns 768-dimensional vectors. `Qwen/Qwen3-Embedding-0.6B` is another supported checkpoint with 1,024-dimensional output. Check license/access requirements before loading.

## Requesting an embedding

<Tabs>
<TabItem label="HTTP">

```bash
curl http://localhost:1234/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "default",
    "input": "task: search result | query: What is graphene?"
  }'
```

Read the vector from `data[0].embedding`.

</TabItem>
<TabItem label="Python">

```python
from mistralrs import EmbeddingRequest, Runner, Which

runner = Runner(which=Which.Embedding(model_id="google/embeddinggemma-300m"))
vectors = runner.send_embedding_request(EmbeddingRequest(
    input=["task: search result | query: What is graphene?"],
    truncate_sequence=True,
))
print(vectors[0])
```

</TabItem>
<TabItem label="Rust">

```rust
use mistralrs::{EmbeddingModelBuilder, EmbeddingRequest};

let model = EmbeddingModelBuilder::new("google/embeddinggemma-300m").build().await?;
let vectors = model.generate_embeddings(
    EmbeddingRequest::builder().add_prompt("task: search result | query: What is graphene?"),
).await?;
```

</TabItem>

## Batching

Pass a list in `input` to embed multiple strings. The response's `data` entries preserve input order.

## Request fields

| Field | Behavior |
| --- | --- |
| `encoding_format` | `float` (default), or `base64` containing little-endian f32 bytes. |
| `truncate_sequence` | Extension: truncate overlong input instead of returning an error. |
| `dimensions` | Unsupported; supplying it returns an error. |

## Normalization

Normalization depends on the checkpoint's `modules.json`; EmbeddingGemma includes a normalization module. If your similarity calculation requires unit vectors and the model does not normalize, apply `v / numpy.linalg.norm(v)` before storing and querying. Check your vector store's metric rather than assuming it performs this step.

## EmbeddingGemma prompts

Prefixes are part of the input; the server does not add them automatically.

| Use | Prefix |
| --- | --- |
| Search query | `task: search result \| query: <query>` |
| Search document | `title: <title or none> \| text: <document>` |
| Question answering | `task: question answering \| query: <question>` |
| Fact verification | `task: fact checking \| query: <claim>` |
| Classification | `task: classification \| query: <text>` |
| Clustering | `task: clustering \| query: <text>` |
| Similarity | `task: sentence similarity \| query: <text>` |
| Code search | `task: code retrieval \| query: <query>` |

These are EmbeddingGemma formats. Follow the selected checkpoint's instructions for other embedding models.

## Using the vectors

Store document vectors, embed each query with the same model, and retrieve nearby vectors with your chosen metric. Your application can then pass the retrieved text to a chat model. See [web search](/guides/agents/web-search/) for retrieval in an agent workflow.
