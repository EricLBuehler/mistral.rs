DiffusionGemma (`google/diffusiongemma-26B-A4B-it`) accepts text and images. It refines blocks of tokens over multiple passes, then commits each block. The standard chat API works, but sampling and streaming differ from autoregressive generation.

## Quick start

```bash
mistralrs run -m google/diffusiongemma-26B-A4B-it
```

Or serve it:

```bash
mistralrs serve -p 1234 -m google/diffusiongemma-26B-A4B-it
curl http://localhost:1234/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "default",
    "messages": [{"role":"user","content":"Why is the sky blue?"}],
    "max_tokens": 1024
  }'
```

Native SDK examples: [Python with images](/examples/python/diffusion-gemma/) and [Rust streaming](/examples/rust/models/diffusion-gemma/).

## What behaves differently

- **Streaming arrives in blocks.** The checkpoint's `canvas_length` sets the block size, normally 256 tokens. Each block arrives after its refinement passes finish.
- **Sampling comes from the checkpoint.** `generation_config.json` controls the temperature schedule and acceptance/stopping thresholds. Request `temperature`, `top_p`, and penalties are ignored; `max_tokens` still caps output.
- **Structured output is not enforced.** Native tool-call parsing works, including calls across block boundaries, but `tool_choice: required`, named tools, and JSON schemas cannot constrain the refinement loop. Validate the model's output in your application.
- **Thinking is enabled by default.** Reasoning is separated into the reasoning field.
- **Concurrency groups matching context lengths.** Those requests refine together; different lengths run in separate groups.
- **Throughput metrics differ.** Prompt T/s covers encoder prefill; decode T/s counts committed tokens over refinement time.
