## LFM3: speech input and output

```bash
mistralrs serve -p 1234 -m LiquidAI/LFM3-Audio-2B --isq q8_0
```

Use `LiquidAI/LFM3-Omni-2B` to add images and video. Both models also load from their `-GGUF` repositories with `--quant`; the companion projector includes the audio components.

For simple synthesis:

```bash
curl http://localhost:1234/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{"model":"default","input":"Hello from mistral.rs.","response_format":"wav"}' \
  --output hello.wav
```

For transcription:

```bash
curl http://localhost:1234/v1/audio/transcriptions \
  -F model=default -F file=@speech.wav
```

Use `/v1/audio/translations` to request an English translation. See the [endpoint example](/examples/server/lfm3-audio-endpoints/) for instructions, speed, output formats, and streaming.

### Chat speech

Send audio using [content parts](/guides/models/multimodal-input/#audio). Text output is the default. For speech, add:

```json
{
  "modalities": ["text", "audio"],
  "audio": {"format": "wav", "voice": "default"}
}
```

Use `["audio"]` for audio-only output. Read base64 bytes from `choices[0].message.audio.data`. Both checkpoints have one default voice and produce mono 24 kHz audio.

LFM3-Audio's task prompts are `Perform ASR in English.`, `Perform TTS in American English using a female voice.`, and `Respond with interleaved text and audio.` The dedicated endpoints and synthesis helpers choose the appropriate prompt. See [Audio](/examples/server/lfm3-audio/) and [Omni](/examples/server/lfm3-omni/) chat examples.

For chat streaming, request `audio.format: "pcm16"` and concatenate decoded `delta.audio.data` bytes in order. Chunks arrive during generation; keep the final tail. [HTTP audio semantics](/reference/http-api/#audio-requests-and-history) covers transcripts and audio-ID history. Native SDKs do not resolve HTTP audio IDs or accept generated `<|audio_out|>` history directly.

### Budgets and limits

- Chat `max_tokens` counts text tokens, speech frames, and control tokens. Increase it when audio ends with `finish_reason: "length"`.
- Text sampling settings do not control speech-code sampling. Omni defaults to temperature 0.4 and repetition penalty 1.2 over 64 frames; Audio uses temperature 1.0, top-k 128, and penalty 1.1 over 4,096 frames. GGUF can supply different embedded defaults. Text temperature 0 does not make speech deterministic.
- Speech disables thinking by default; explicit reasoning controls are preserved.
- Audio output rejects tool calls, constrained decoding, custom logits processors, and logprobs. OpenAI named voices and Realtime are unsupported.

### Native SDKs

Load LFM3 with Rust's `ModelBuilder` or Python's `Which.MultimodalPlain`. Call `Model::generate_speech(prompt)` or `Runner.generate_audio(prompt)` to receive PCM, sample rate, and channels. The [Rust example](/examples/rust/models/lfm3-audio/) saves WAV. For mixed output or streaming, use the [Rust audio builder](/reference/rust-sdk/#chat-speech-output) or Python's `modalities` and `audio` fields.

## Voxtral Realtime: audio in, text out

```bash
mistralrs serve -m mistralai/Voxtral-Mini-4B-Realtime-2602
```

Use the transcription request above or an audio chat content part. This checkpoint is intended for transcription; arbitrary audio question answering is not implied. The older `VoxtralForConditionalGeneration` architecture is unsupported.

Native SDKs load Voxtral as a multimodal model and send audio through their normal [multimodal requests](/guides/models/multimodal-input/).

## Dia: text-to-speech

```bash
mistralrs serve -m nari-labs/Dia-1.6B
```

Use `/v1/audio/speech` as above, with dialogue tags such as `[S1]` and `[S2]` in `input`. Dia also understands parentheticals such as `(laughs)`.

- `voice` must be omitted or `default`.
- Formats are MP3 (default), Opus, AAC, FLAC, WAV, and PCM. Compressed output and speed adjustment require FFmpeg on the server's PATH.
- `speed` ranges from 0.25 to 4.0. Dia rejects nonempty `instructions` and SSE speech streaming; ordinary responses contain the completed audio file.

Native SDKs use `SpeechModelBuilder` / `Which.Speech` and the same `generate_speech` / `generate_audio` helpers. Complete Dia examples: [Python](/examples/python/dia/) and [Rust](/examples/rust/models/speech/). See [audio compatibility](/reference/openai-compatibility/#audio) for endpoint restrictions shared across models.
