## Quick start

```bash
mistralrs run -f /path/to/model.gguf
mistralrs serve -m unsloth/Qwen3.5-4B-GGUF --quant 4
```

The `.gguf` suffix selects the format automatically. Supported models use their normal inference APIs after loading, including [decision requests](/guides/models/use-decision-models/) and [LFM3 speech](/guides/models/use-speech-models/). Check [GGUF compatibility](/reference/gguf-support/) before downloading a checkpoint.

## Select a GGUF file

| Goal | Command |
| --- | --- |
| Exact local file | `mistralrs run -f /path/model-Q4_K_M.gguf` |
| Exact Hub file | `mistralrs run -m owner/repo -f model-Q4_K_M.gguf` |
| Published bit width | `mistralrs run -m owner/repo --quant 4` |
| Local GGUF directory | `mistralrs run -m /path/to/gguf-dir --quant 4` |

Replace `run` with `serve` or `bench` without changing model flags. `--quant 4` prefers Q4_K_M when available; use `-f` for an exact variant or a repository containing several independent models. `--quant auto` does not select GGUF artifacts. If a directory mixes weight formats, add `--format gguf`.

Split files use semicolon-separated names:

```bash
mistralrs run -m owner/repo \
  -f 'model-00001-of-00002.gguf;model-00002-of-00002.gguf'
```

Without `-m`, local shards must share a directory.

## Model assets and projectors

The loader uses embedded tokenizer, template, and configuration metadata where supported. It can find missing assets through GGUF base-model metadata. Multimodal models require a compatible companion projector; repository selection prefers a matching dtype. With the direct local `-f` shorthand, an unambiguous adjacent projector is selected automatically.

Use overrides when discovery is ambiguous or incomplete:

| Option | Purpose |
| --- | --- |
| `--mmproj <file.gguf>` | Select projector files; separate multiple components with semicolons. |
| `--tok-model-id <id-or-path>` | Supply original configuration, tokenizer, or processor assets. |
| `-t <tokenizer.json>` | Supply a tokenizer directly. |
| `-c <template>` | Override the chat template. |

For standalone d1 GGUF, original assets are optional and enable additional [decision question types](/guides/models/use-decision-models/#use-gguf).

## Multimodal GGUF

Pass media through the usual CLI flags or API content parts:

```bash
mistralrs run -m unsloth/gemma-4-E4B-it-GGUF --quant 4 \
  --image photo.jpg -i "Describe this image."
```

Image, audio, and video support depends on the model and projector. See [multimodal requests](/guides/models/multimodal-input/) and the [compatibility table](/reference/gguf-support/#multimodal-model-families).

## Python and Rust

Select exact artifacts in the SDKs. Omit the projector field for text-only models; use the selected repository's actual filenames.

<Tabs>
<TabItem label="Python">

```python
from mistralrs import Runner, Which

runner = Runner(which=Which.GGUF(
    quantized_model_id="unsloth/gemma-4-E4B-it-GGUF",
    quantized_filename="gemma-4-E4B-it-Q4_K_M.gguf",
    mmproj_filename="mmproj-BF16.gguf",
))
```

[Complete Python example](/examples/python/gguf/).

</TabItem>
<TabItem label="Rust">

```rust
use mistralrs::GgufModelBuilder;

let model = GgufModelBuilder::new(

.await?;
```

## GGUF with dynamic LoRA

```bash
mistralrs serve -m Qwen/Qwen2.5-0.5B-Instruct-GGUF --quant 4 \
  --lora philosophy=closestfriend/brie-qwen2.5-0.5b
```

Requests select a loaded adapter by alias. Multimodal adapters apply only to the language model. Some GGUF rotary layouts are incompatible with canonical LoRA weights; check [feature compatibility](/reference/gguf-support/#feature-compatibility). See [LoRA management](/guides/customize/lora-adapters/) for request routing.

## Requantize with ISQ

`--quant` selects a published artifact. `--isq` converts compatible weights from an exact file during loading:

```bash
mistralrs run -f /path/model-BF16.gguf --isq q4k
```

Start from high precision where possible to avoid compounding quantization loss. K-quants can use `--imatrix` or `--calibration-file`; see [quantization](/guides/quantization/quantize-a-model/).

## Run offline

```bash
HF_HUB_OFFLINE=1 mistralrs run -f /models/model-Q4_K_M.gguf
```

Every required asset must be local or cached. Models with sufficient embedded metadata need no original config. Others need cached original assets or a local `--tok-model-id /models/original-assets` directory. Multimodal models still need their projector.

See [cache locations](/guides/models/run-any-model/#running-offline). A complete local main GGUF plus projector is sufficient for LFM3-VL, Audio, Omni, and the standalone d1 question subset.

## Migrating existing GGUF commands

You can omit `--format gguf` for `.gguf` files and `-m .` for a local filename. Keep explicit asset/projector overrides when the source is ambiguous.

## Troubleshooting

| Symptom | Action |
| --- | --- |
| No artifact matches `--quant` | Choose a published bit width or an exact `-f` file. |
| Unsupported architecture or storage type | Check [GGUF compatibility](/reference/gguf-support/); most IQ matrix formats are unsupported. |
| Missing or ambiguous projector | Select the matching file with `--mmproj`. |
| Missing configuration or processor assets | Supply the original ID or local assets with `--tok-model-id`. |
| Unsupported tokenizer profile | Supply the original `tokenizer.json` with `-t` or `--tok-model-id`. |
