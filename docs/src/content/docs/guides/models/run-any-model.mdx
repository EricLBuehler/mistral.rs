---
title: Run models
description: Load a Hugging Face checkpoint or local model, choose quantization, and run offline.
---

Start an interactive chat or an OpenAI-compatible server:

```bash
mistralrs run -m Qwen/Qwen3-4B
mistralrs serve -p 1234 -m Qwen/Qwen3-4B
```

For a single prompt, add `-i "Your question"` to `run`. In interactive chat, `/help` lists commands, `/clear` resets the conversation, and `/exit` quits.

The CLI detects supported model architectures. For embeddings, speech, decisions, or image generation, use the request API listed in [Choose a model](/guides/models/choose-a-model/). Native SDK examples: [Python](/examples/python/plain/) and [Rust](/examples/rust/getting-started/text-generation/).

## Select a quantization with `--quant`

```bash
mistralrs run -m Qwen/Qwen3-4B --quant 4
```

For a standard Hub model, `--quant` loads a matching community UQFF when available, otherwise quantizes during loading (ISQ). It accepts bit widths `2`, `3`, `4`, `5`, `6`, `8` and supported [quantization names](/reference/quantization-types/). `--quant auto` selects a level based on hardware, or full precision if it fits.

For a GGUF repository, `--quant` selects an existing artifact; `auto` is unsupported. Use `--isq` to force runtime conversion or `--from-uqff` to select a specific UQFF instead of `--quant`. See [quantize a model](/guides/quantization/quantize-a-model/) for format and quality tradeoffs.

## Local model directories

```bash
mistralrs run -m /path/to/model-dir
```

The directory should contain the checkpoint weights and configuration. Safetensors and Mistral-native `consolidated.safetensors` layouts are supported. Local `--quant` uses ISQ, or selects an artifact in a GGUF-only directory. If the directory mixes formats, add `--format gguf` to select GGUF.

## Run GGUF models

```bash
mistralrs run -f /path/to/model.gguf
mistralrs serve -m unsloth/Qwen3.5-4B-GGUF --quant 4
```

The filename selects GGUF automatically. Multimodal models also need a companion projector; some need original model assets. See [Run GGUF models](/guides/models/run-gguf/) for discovery, overrides, and SDK loading, and [GGUF compatibility](/reference/gguf-support/) for supported formats.

## Forcing an architecture

For a text checkpoint with a nonstandard config, `--arch` forces its loader. Accepted names are lowercase forms of the [supported architectures](/reference/supported-models/). Other CLI model categories are auto-detected. Python selectors expose an optional `arch` field.

## Chat template overrides

For a missing or incorrect template, pass `-c/--chat-template <file>` or `--jinja-explicit <file>`. Bundled overrides live in `chat_templates/`. See [chat templates](/guides/customize/chat-templates/) before changing a working checkpoint template.

## Running offline

Populate the cache online, then disable Hub access:

```bash
mistralrs run -m Qwen/Qwen3-4B
HF_HUB_OFFLINE=1 mistralrs serve -m Qwen/Qwen3-4B
```

Offline mode uses local files and cached repository listings; missing assets fail immediately. `mistralrs cache list` shows cached models. The cache location is `$HF_HUB_CACHE`, then `$HF_HOME/hub`, then `~/.cache/huggingface/hub`.

A local multimodal GGUF can still need external processor/configuration assets. Cache those too, or supply a local directory with `--tok-model-id`. See [GGUF offline loading](/guides/models/run-gguf/#run-offline) and [environment variables](/reference/environment-variables/).
