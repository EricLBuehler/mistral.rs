<Tabs>

```bash
mistralrs run -m Qwen/Qwen3-VL-4B-Instruct \
  --image photo.jpg -i "What is this?"
```

`--image`, `--audio`, and `--video` accept multiple values and require `-i`. Interactive chat also detects local file paths in prompts.

Replace the example URL with a publicly reachable image:

```bash
curl http://localhost:1234/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "default",
    "messages": [{"role": "user", "content": [
      {"type": "image_url", "image_url": {"url": "https://example.com/photo.jpg"}},

```

For a client-local file, send a base64 data URL as shown [below](#in-memory-images-from-python).

<TabItem label="Python">

```python
from mistralrs import ChatCompletionRequest, Runner, Which

runner = Runner(which=Which.MultimodalPlain(model_id="Qwen/Qwen3-VL-4B-Instruct"))
response = runner.send_chat_completion_request(ChatCompletionRequest(
    model="default",
    messages=[{"role": "user", "content": [
        {"type": "image_url", "image_url": {"url": "file:///absolute/path/photo.jpg"}},
        {"type": "text", "text": "Describe this image."},
    ]}],
    max_tokens=256,
))
print(response.choices[0].message.content)
```

Local file URLs work in the native SDK; HTTP requests use public URLs or inline data.

</TabItem>

use mistralrs::{ModelBuilder, MultimodalMessages, TextMessageRole};

## Content parts and URL forms

| Part | Payload |
| --- | --- |
| `text` | `{"text":"Your question"}` |
| `image_url` | `{"image_url":{"url":"..."}}` |
| `video_url` | `{"video_url":{"url":"..."}}` |
| `audio_url` | `{"audio_url":{"url":"..."}}` |
| `input_audio` | `{"input_audio":{"data":"BASE64","format":"wav"}}` |

Each part also includes its `type`, as in the examples. HTTP URL parts accept public HTTP(S) URLs and `data:<mime>;base64,...`. They do not accept local paths, `file://` URLs, or private-network URLs. The CLI and native SDKs can read local media.

## Video

Send `--video clip.mp4` or a content part:

```json
{"type":"video_url","video_url":{"url":"https://example.com/clip.mp4"}}
```

Non-GIF video requires [FFmpeg on the server PATH](/guides/models/video-setup/). Frame sampling follows the model configuration; per-request sampling controls are not exposed. Video soundtracks are not extracted automatically: attach audio separately when the model supports it.

## Audio

Standard WAV/MP3 input uses encoded file bytes without a data-URL prefix:

```json
{"type":"input_audio","input_audio":{"data":"BASE64_FILE_BYTES","format":"wav"}}
```

For URLs or other supported formats, use `audio_url`. WAV, MP3, FLAC, and OGG decode natively; convert unsupported formats before sending. Rust accepts decoded `AudioInput`. Request limits are in [HTTP audio semantics](/reference/http-api/#audio-requests-and-history).

Audio input does not imply speech output. For LFM3 speech generation or transcription endpoints, see [Speech models](/guides/models/use-speech-models/).

## In-memory images from Python

A data URL works with either the OpenAI HTTP client or the native SDK:

```python
import base64
from pathlib import Path

payload = base64.b64encode(Path("photo.jpg").read_bytes()).decode("ascii")
messages = [{"role": "user", "content": [
    {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{payload}"}},
    {"type": "text", "text": "Describe this image."},
]}]
```

For a PIL image, save it to `io.BytesIO` first and use the matching MIME type.

## Mixing modalities in one request

Keep parts in the order you want the model to receive them. For example, send an image, an audio question, then a text instruction. Use a model that supports all those inputs, such as LFM3-Omni. See the [Omni example](/examples/server/lfm3-omni/).

## Preprocessing

The model's processor resizes/patches images, samples video frames, and resamples audio. There is no universal fixed image resolution across models. Load-time bounds use `--max-num-images`, `--max-edge`, and `--max-image-length`; per-request preprocessing overrides are not exposed.
