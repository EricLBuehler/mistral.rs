Most checkpoints need only `mistralrs run -m <model-id>`. Use [Choose a model](/guides/models/choose-a-model/) to find the right task and [supported models](/reference/supported-models/) for the architecture inventory. This page covers exceptions to the usual loading and request behavior.

## Reasoning controls

`reasoning_effort` accepts `off`, `low`, `medium`, `high`, and `xhigh`; `none` aliases `off`. An explicit positive effort enables thinking; `off` disables it. The legacy `enable_thinking` boolean also works, but contradictory explicit settings return an error.

These are chat-template inputs. Each checkpoint decides which tiers it recognizes. With neither setting supplied, thinking is normally enabled; speech requests and model templates can choose different defaults.

## Thinking models (Qwen3, SmolLM3)

Disable default thinking with `--thinking false` on the CLI or `enable_thinking: false` in a chat request:

```bash
mistralrs run -m Qwen/Qwen3-4B --thinking false
```

`--reasoning-effort` also applies to interactive and one-shot requests. Qwen3 templates recognize inline `/think` and `/no_think` instructions.

Published FP8 checkpoints load directly, without `--quant`. For example:

```bash
mistralrs serve -m Qwen/Qwen3.8-27B-FP8 --pa-cache-type f8e4m3 --max-seqs 16
```

## Flint

```bash
mistralrs run -m RecursiveSI/flint --quant 4
```

Flint supports ISQ, MoQE, UQFF, and GGUF; X-LoRA and NVFP4 GGUF are unsupported. Its template chooses when to reason and ignores `enable_thinking` and `reasoning_effort`. Preserve assistant `reasoning_content` when sending conversation history back, including tool-call turns.

Tool calls use the normal API; send tool definitions on every request. See the [Flint tool example](/examples/server/flint-tools/). Long reasoning may exhaust the output budget: check `finish_reason: "length"` before treating a partial answer as complete.

## MoE models and MoQE

[MoQE](/guides/quantization/quantize-a-model/) quantizes routed experts while leaving other weights at their existing precision:

```bash
mistralrs run -m Qwen/Qwen3-30B-A3B --isq 4 --isq-organization moqe
```

Use it during ISQ or UQFF creation. It does not rewrite an already-quantized GGUF or UQFF selected by `--quant`. Python uses `organization=IsqOrganization.MoQE` on the model selector. Quantization can change routing and outputs.

## MLA models (DeepSeek V2/V3, GLM-4.7-Flash)

These models store a compact latent KV cache. CUDA paged attention can use specialized MLA kernels. For suspected kernel problems, compare with `MISTRALRS_NO_MLA=1` and then `--paged-attn off`. See [paged attention](/guides/perf/paged-attention/) for memory sizing.

## GPT-OSS

Load published MXFP4 expert weights without an extra quantization flag:

```bash
mistralrs run -m openai/gpt-oss-20b
```

ISQ applies to attention layers and the output head; experts are already quantized.

## Qwen3 Next

Qwen3-Next and Qwen3-Coder-Next share a loader. Their recurrent and attention layers have different cache costs from a pure attention model; use automatic memory sizing before manually reserving KV capacity.

## Qwen3.5 and Qwen3.6

Both dense and MoE variants are supported. To extend context with YaRN, override the model config as well as the serving limit:

```bash
mistralrs serve -m Qwen/Qwen3.5-27B \
  --hf-overrides '{"text_config":{"rope_parameters":{"rope_type":"yarn","factor":4.0,"original_max_position_embeddings":262144}}}' \
  --max-model-len 1010000
```

Overrides merge recursively. `--max-model-len` alone does not enable RoPE scaling, and static YaRN can reduce short-context quality.

## Qwen3.8-Flash-Next

This is a large hybrid MoE model with a hashed embedding table (PLE). Use quantization to reduce memory; CUDA builds need `cuda,flash-attn,cutile`:

```bash
mistralrs serve -m Qwen/Qwen3.8-Flash-Next --quant 4
```

- PLE placement is automatic. The table can remain in host memory when it does not fit on the device, increasing prompt-processing cost. CPU and Metal gather its rows on the host.
- Paged attention is CUDA-only; use `--paged-attn off` elsewhere. FP8 KV caches and tensor parallelism are unsupported.
- Built-in `--mtp` works with safetensors or UQFF containing MTP weights. `--mtp-n-predict N` fixes draft depth. MTP uses extra memory and recomputes cached prompt prefixes.
- GGUF supports text, images, and video, including packed PLE weights. GGUF MTP, external MTP, and DFlash drafters are unsupported.

For GGUF, use `mistralrs run -m unsloth/Qwen3.8-Flash-Next-GGUF --quant 4`. Keep automatic memory sizing unless you need a fixed shared `--kv-cache`; `--max-model-len` instead limits each request. See [memory budgeting](/guides/perf/paged-attention/#memory-budget).

## Granite 4.0 (GraniteMoeHybrid)

Granite 4.0 hybrid checkpoints, such as `ibm-granite/granite-4.0-micro`, load automatically. They combine recurrent and attention layers.

## LFM2 and LFM2.5

Dense, MoE, and VL variants are supported; VL accepts images. The checkpoint's Liquid tool-call template is detected automatically.

## LFM3 and LFM3-VL

`LiquidAI/LFM3-1.7B` accepts text; `LiquidAI/LFM3-VL-2B` also accepts images and video. Both support safetensors, ISQ, UQFF, and GGUF. For example:

```bash
mistralrs run -m LiquidAI/LFM3-VL-2B --isq q4k \
  --image photo.jpg -i "Describe this image."
```

VL video sampling uses 2 FPS and 4 to 768 frames. ISQ covers the language model and projector; the vision encoder remains unquantized. See [multimodal input](/guides/models/multimodal-input/) and [GGUF loading](/guides/models/run-gguf/).

## LFM3-Audio

`LiquidAI/LFM3-Audio-2B` accepts text and audio and returns text, speech, or both. Use LFM3-Omni when images or video are also needed. See [speech input and output](/guides/models/use-speech-models/#lfm3-speech-input-and-output) for requests and task prompts.

## LFM3-Omni

`LiquidAI/LFM3-Omni-2B` accepts text, images, audio, and video together and returns text, speech, or both. Video uses 2 FPS and 4 to 384 frames; submit its soundtrack separately as audio.

Both Audio and Omni support safetensors, ISQ, UQFF, and standalone GGUF with a companion projector. Paged attention, chunked prefill, and media embedding caching are supported. Speech encoders, the audio projector, depth decoder, and codec remain unquantized during ISQ; Omni also keeps its vision encoder unquantized. See the [Omni example](/examples/server/lfm3-omni/).

## d1 and d1-Omni

Decision models answer named questions through `/v1/systemone` or `send_decision_request`, rather than chat generation. d1 accepts text, images, and video; d1-Omni also accepts audio and spoken instructions.

Standalone GGUF supports `noul`, single-selection `choice`, and `score`. Other question types require the original model configuration and calibration. Start with [Use decision models](/guides/models/use-decision-models/).

### LFM3 speech input and output

Speech behavior, formats, output budgets, and SDK helpers are collected in [Speech models](/guides/models/use-speech-models/#lfm3-speech-input-and-output).

## Gemma

For gated repositories, accept the license on Hugging Face and authenticate with `mistralrs login`. Gemma 4 accepts image, audio, and video parts and constrains its tool-call format by default; see [tool calling](/guides/agents/tool-calling-basics/).

## Muse Glimmer

`meta-models/Muse-Glimmer-30B` accepts text, images, and video from safetensors; audio is unsupported. Its ATEM template and tool calls are detected automatically. `reasoning_effort` maps to its `reasoning_strength` setting; omission uses the template's `high` default.

ISQ, UQFF, paged attention, prefix caching, tensor parallelism, and text-backbone LoRA are supported. GGUF needs original model assets and supports images only; see [GGUF compatibility](/reference/gguf-support/#multimodal-model-families).

## MatFormer

Gemma 3n can load a smaller slice of the same checkpoint:

```bash
mistralrs run -m google/gemma-3n-E4B-it \
  --matformer-config-path matformer_configs/gemma3n.csv \
  --matformer-slice-name "Config for E2.49B (block-level)"
```

Without a slice, the full configuration loads. The bundled CSV includes E4B, E2B, and intermediate slices. The same `matformer_config_path` and `matformer_slice_name` settings are available in TOML/Python; Rust builders use `with_` methods of those names.

## Mistral Small tool calling

For checkpoints missing a suitable template, use the bundled override:

```bash
mistralrs serve -m mistralai/Mistral-Small-3.2-24B-Instruct-2506 --quant 4 \
  --jinja-explicit chat_templates/mistral_small_tool_call.jinja
```

## LLaVA chat templates

Vicuna-backed checkpoints need the Vicuna template; Mistral-backed checkpoints use the default:

```bash
mistralrs run -m llava-hf/llava-v1.6-vicuna-7b-hf \
  -c chat_templates/vicuna.json --image photo.jpg -i "Describe this image."
```

## Qwen3-VL

Video frame sampling follows the model configuration; per-request overrides are not exposed.

## Llama 4

Scout's full 10M-token context requires a large memory budget, generally with paged attention and multi-GPU tensor parallelism. Set a smaller `--max-model-len` when that capacity is unnecessary.

## Multimodal device mapping

Device mapping primarily distributes the text backbone. Media encoders follow their model-specific device paths; do not assume every component is split across GPUs.

## Phi

Phi 3.5 Vision works best with one image; multiple images are resized together. Phi 4 Multimodal accepts images and audio in one message. Phi 3.5 MoE supports [MoQE](#moe-models-and-moqe).

## DiffusionGemma

See [block-diffusion models](/guides/models/use-block-diffusion/) for sampling, streaming, and tool-call limitations.
