Dynamic LoRA lets each request use the base model or one loaded adapter. Compatible language-model adapters work with text and multimodal models, including supported GGUF models. Vision, audio, and projector adapters are not supported.

| Mode | Use |
|---|---|
| Dynamic LoRA | Select one adapter per request; replace aliases without interrupting active requests. |
| [Legacy LoRA](#legacy-raw-lora) | Static adapters for GGML and compatible Phi3 GGUF loads. |
| [X-LoRA](#x-lora) | Mix multiple adapters per token with a learned classifier. |

## Enable and preload LoRA

Give each adapter an alias and a Hugging Face repository or local directory. Preloading enables the runtime automatically.

<Tabs>
<TabItem label="CLI">

```bash
mistralrs serve -m <base-model> --lora code=<adapter-repo> --lora math=./math-adapter
```

For interactive use, add `--adapter code` to `run`. `/adapter <alias>` switches adapters; `/adapter none` returns to the base model and `/adapter list` lists aliases.

</TabItem>
<TabItem label="Python">

```python
from mistralrs import LoraAdapter, Runner, Which

runner = Runner(which=Which.Lora(
    model_id="<base-model>",
    adapters=[LoraAdapter(alias="code", source="<adapter-repo>")],
))
```

</TabItem>
<TabItem label="Rust">

```rust
use mistralrs::{LoraModelBuilder, TextModelBuilder};

let model = LoraModelBuilder::from_text_model_builder(
    TextModelBuilder::new("<base-model>"),
)
.with_adapter("code", "<adapter-repo>")
.build()
.await?;
```

</TabItem>
</Tabs>

To load adapters later, start with `--enable-lora`, Python's `Which.Lora(model_id=...)`, or a Rust `LoraModelBuilder` without adapters.

For GGUF, use the same CLI flags. Python's `Which.GGUF` accepts `adapters=[LoraAdapter(...)]`; Rust's `GgufModelBuilder` accepts `.with_lora_adapter(alias, source)`. Enable an empty GGUF runtime with `adapters=[]` or `.with_lora()`. Select model files and projectors as described in [Run GGUF models](/guides/models/run-gguf/).

Remote adapter revisions default to `main`, independently of the base model. Pin one with `LoraAdapter(..., revision="<commit>")`, Rust's `.with_adapter_revision(alias, source, revision)`, or CLI `--lora-modules '{"name":"code","path":"org/adapter","revision":"<commit>"}'`. Structured [TOML configuration](/reference/cli-toml-config/) also supports revisions.

| Limit | Default |
|---|---:|
| `--lora-max-adapters` | 16 aliases and resident generations |
| `--lora-max-rank` | 256 |
| `--lora-max-bytes` | 8 GiB |

These limits apply to adapters, not total model memory. Leave room for both generations during replacement: active requests keep the old one resident. Python exposes the limits on `Which.Lora` and `Which.GGUF`; Rust uses `with_runtime_config` or `with_lora_runtime_config`.

## Select an adapter per request

<Tabs>
<TabItem label="HTTP">

```json
{
  "model": "default",
  "adapter": "code",
  "messages": [{"role": "user", "content": "Write a binary search."}]
}
```

Chat Completions, Completions, and Responses accept `adapter`. Alternatively, use an adapter model ID from `GET /v1/models` as `model`, without an `adapter` field. Qualified IDs such as `<base-model>::code` avoid ambiguity across base models.

</TabItem>
<TabItem label="Python">

```python
from mistralrs import ChatCompletionRequest

response = runner.send_chat_completion_request(ChatCompletionRequest(
    model="default",
    adapter="code",
    messages=[{"role": "user", "content": "Write a binary search."}],
))
```

</TabItem>
<TabItem label="Rust">

```rust
use mistralrs::{RequestBuilder, TextMessageRole};

let response = model.send_chat_request(
    RequestBuilder::new()
        .set_adapter("code")
        .add_message(TextMessageRole::User, "Write a binary search."),
).await?;
```

</TabItem>
</Tabs>

Omit the adapter to use the base model. Unknown aliases return an error. Each request keeps its selected generation even if the alias is replaced or unloaded.

For repeatable retries, pass `{"generation":"<generation-id>"}` as `adapter`. Get the ID from load/list status or the response's `adapter_generation`. Exact selection works only while that generation is resident. Read the ID before the first request if it must also use that generation.

## Hot-load, list, and unload

Live updates require a single-process deployment and a local directory containing `adapter_config.json` and one `adapter_model.safetensors` file. Tensor-parallel deployments support preloads only.

<Tabs>
<TabItem label="HTTP">

```bash
curl http://localhost:1234/v1/load_lora_adapter -H 'Content-Type: application/json' -d '{"lora_name":"code","lora_path":"/srv/adapters/code-v1"}'
curl http://localhost:1234/v1/lora_adapters
curl http://localhost:1234/v1/unload_lora_adapter -H 'Content-Type: application/json' -d '{"lora_name":"code"}'
```

Enable mutation as shown below. For multi-model servers, add `model` to mutation bodies or `?model=<id>` when listing.

</TabItem>
<TabItem label="Python">

```python
loaded = runner.load_lora_adapter("code", "./code-v1")
status = runner.lora_adapter_status()
runner.unload_lora_adapter("code")
```

Failures raise `LoraAdapterError`, a `ValueError` subclass with a stable `code` attribute.

</TabItem>
<TabItem label="Rust">

```rust
let loaded = model.load_lora_adapter("code", "./code-v1").await?;
let status = model.lora_adapter_status().await?;
model.unload_lora_adapter("code").await?;
```

</TabItem>
</Tabs>

To replace an HTTP alias, send `load_inplace: true`. Add `expected_generation` from list/load to reject a concurrent change with HTTP 409. Unload accepts the same guard. Rust exposes `LoraAdapterLoadPolicy::CompareAndSwap` and `unload_lora_adapter_if_generation`; Python accepts `expected_generation` on the lifecycle methods.

Failed replacements leave the current alias intact. Unload prevents new selections but lets active requests finish. Concurrent loads return `lora_load_busy` (HTTP 429); retry with backoff. A load may finish after a client timeout, so inspect status before retrying.

### Enable HTTP mutation

```bash
MISTRALRS_ALLOW_RUNTIME_LORA_UPDATING=1 MISTRALRS_LORA_ADAPTER_ROOT=/srv/adapters mistralrs serve -m <base-model> --enable-lora
```

Listing is available without mutation. Protect mutation endpoints with authentication or a reverse proxy. The configured root restricts server-local paths; without it, clients can request any readable adapter directory. Keep the root and adapter directories operator-owned. Publish complete adapters at new immutable paths rather than changing files while they may be loaded. Symlinks escaping the root are rejected.

## Production rollout and recovery

Load new files under a canary alias, validate output, then replace the production alias with an `expected_generation` guard. Keep the previous files for rollback. Monitor `resident_bytes` and `retired_generations` while old requests drain.

Runtime-loaded aliases do not survive restarts or model reloads. Put required startup adapters in preload configuration.

## Routed MoE adapters

Routed-expert LoRA uses the same APIs. Supported families include DeepSeek V2/V3/R1, Flint, GLM-4.7/Flash, GPT-OSS, Hunyuan MoE, LFM2/2.5 MoE, Mixtral, Phi-3.5-MoE, Qwen3 MoE/Next/Coder-Next/VL MoE, Qwen3.5/3.6 MoE, Llama 4, and Gemma 4. Multimodal adapters apply to the language model only. Granite MoE and dynamic LoRA on AnyMoE are unsupported.

```bash
mistralrs serve -m Qwen/Qwen3-30B-A3B --lora domain=<moe-adapter-repo>
```

## Support matrix

| Area | Support and limits |
|---|---|
| Base weights | Compatible safetensors, ISQ, UQFF, and [GGUF](/reference/gguf-support/). |
| Devices | CPU, Metal, CUDA; tensor parallelism supports preloads only. |
| Requests | Chat Completions, Completions, Responses; not Embeddings, Anthropic Messages, diffusion, or dedicated speech. |
| Files | PEFT config plus one safetensors file; no pickle, sharded adapters, extra vocabulary, or adapter tokenizers. |
| Formats | Standard LoRA and RS-LoRA, including supported routed experts and compatible rank/alpha/target/exclude patterns. |
| Speculative decoding | Dynamic LoRA is unsupported. |

DoRA, aLoRA, QALoRA, BD-LoRA, Arrow, MonteCLoRA, adapter bias, `modules_to_save`, layer replication, non-expert `target_parameters`, weight tying, trainable-token indices, Megatron configuration, and embedding/output-head changes are unsupported. Base-transforming initializers such as PiSSA, OLoRA, CorDA, LoftQ, and LoRA-GA must be converted to ordinary LoRA for the original base. Unsupported contents are rejected, not partially loaded.

Full examples: [Python](/examples/python/lora/), [Rust](/examples/rust/advanced/lora/), and [HTTP](/examples/server/adapter-chat/).

## Migrating from mistral.rs 0.9.0 and older

Replace static adapter lists with named adapters and select one per request: CLI `--lora alias=source`, Python `LoraAdapter(alias=..., source=...)`, or Rust `.with_adapter(alias, source)`. Replace `set_adapters` with `set_adapter`. There is no dynamic equivalent to stacking several adapters in one request; use X-LoRA or premerged weights.

GGML and supported static GGUF configurations use `--legacy-lora` with `--legacy-lora-order`. See [TOML configuration](/reference/cli-toml-config/) for migrated config fields.

## Migrating from vLLM

`--lora-modules`, `--enable-lora`, `--max-lora-rank`, and alias-as-model requests are accepted. Set `MISTRALRS_ALLOW_RUNTIME_LORA_UPDATING=1` for mutation. Lifecycle endpoint names match vLLM, but response/error bodies and limits differ; this is not a drop-in lifecycle API. In particular, `--lora-max-adapters` limits resident generations, not active adapters per batch. Resolver plugins, adapter dtype overrides, and fully sharded LoRA are unavailable.

## Troubleshooting

| Error | Action |
|---|---|
| `lora_runtime_unavailable` | Start with a preload or enable an empty runtime; check tensor-parallel restrictions. |
| `lora_load_busy` | Retry with backoff. |
| `lora_adapter_already_loaded` / `lora_generation_mismatch` | Refresh status before replacing or unloading. |
| `lora_adapter_not_found` | Refresh aliases; the selected generation may no longer be resident. |
| Rank, adapter, or byte limit exceeded | Use a smaller adapter, free capacity, or raise the relevant limit with memory headroom. |
| `invalid_lora_adapter` | Check PEFT format, supported features, and the exact base-model weights. |
| Path/file forbidden | Publish an immutable adapter below the configured root with correct permissions. |

Pass generation IDs exactly as returned. Compatibility checks cannot prove that an adapter was trained from the correct base weights.

## Legacy raw LoRA

Use the publisher's ordering JSON with `--legacy-lora-order`. A minimal single-adapter file is:

```json
{"base_model_id": "org/base-model", "order": ["adapter"]}
```

The base ID and adapter names must match the selected files. Preserve any publisher-supplied `layers` mapping. See [GGUF support](/reference/gguf-support/) for compatible static configurations.

## X-LoRA

X-LoRA mixes adapters per token and has no dynamic selection or hot-loading API.

<Tabs>
<TabItem label="CLI">

```bash
mistralrs run -m <base-model> --xlora <xlora-repo> --xlora-order <ordering-file.json>
```

Both flags are required and conflict with other LoRA modes.

</TabItem>
<TabItem label="Python">

```python
runner = Runner(which=Which.XLora(
    model_id="<base-model>",
    xlora_model_id="<xlora-repo>",
    order="<ordering-file.json>",
))
```

</TabItem>
<TabItem label="Rust">

```rust
let model = XLoraModelBuilder::from_text_model_builder(
    TextModelBuilder::new("<base-model>"),
    "<xlora-repo>",
    serde_json::from_reader(std::fs::File::open("<ordering-file.json>")?)?,
).build().await?;
```

</TabItem>
</Tabs>

Full examples: [Python](/examples/python/xlora-zephyr/) and [Rust](/examples/rust/advanced/xlora/).

## AnyMoE

AnyMoE combines compatible fine-tunes and trains a router from a small JSON calibration dataset. Use Rust's `AnyMoeModelBuilder` or Python's `AnyMoeConfig`; there is no CLI configuration. Dynamic per-request LoRA cannot wrap AnyMoE, but LoRA-backed experts are supported.

See the [Python reference](/reference/python/anymoe/) and [Python](/examples/python/anymoe/), [Rust](/examples/rust/advanced/anymoe/), and [LoRA expert](/examples/rust/advanced/anymoe-lora/) examples.
