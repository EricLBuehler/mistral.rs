`mistralrs serve` and `mistralrs from-config` enable HTTP access logs and `/metrics` by default.

## Access logs

Each request produces a start and completion event with its request ID, route, model, status, and duration. Probes, docs/UI requests, and CORS preflight are skipped by default.

| Option | Effect |
| --- | --- |
| `--access-log-format json` | Write access-log messages as JSON object strings. Default: `text`. |
| `--access-log-health` | Include probes and docs/UI requests. |
| `--disable-access-log` | Disable info-level HTTP access events. |
| `-v`, `-vv`, `RUST_LOG` | Control logging verbosity. |

:::caution
`-l, --log <path>` records full model requests and responses. It is separate from access logging; use it only where payloads can be stored safely.
:::

## Request ids

Send `x-request-id` to correlate client and server logs. The server generates an ID when absent and echoes it in the response. `--disable-request-id-header` disables the response header while retaining IDs in logs.

## Prometheus metrics

Configure Prometheus to scrape the server:

```yaml
scrape_configs:
  - job_name: mistralrs
    static_configs:
      - targets: ["localhost:1234"]
```

Use the server's reachable address when Prometheus runs elsewhere. `--disable-metrics` disables collection and makes `/metrics` return 503.

### HTTP metrics

Monitor request count, duration, in-flight requests, and body size by route and model. [Metric names and labels](/reference/metrics/#http-metrics).

### Streaming latency

Track time to first token and inter-token latency. [Streaming metrics](/reference/metrics/#streaming-latency).

### Engine metrics

Track throughput, queue length, cache utilization, and cache hits. These counters are process-wide, so use separate processes for per-model engine dashboards. [Engine metrics](/reference/metrics/#engine-metrics).

### Speculative decoding (MTP)

Track proposed and accepted tokens to assess whether speculation helps your workload. [Speculative decoding metrics](/reference/metrics/#speculative-decoding-mtp).

## Useful PromQL

Use rates for counters and histogram quantiles for latency:

```promql
# Fraction of proposed draft tokens that were accepted
rate(mistralrs_speculative_draft_tokens_accepted_total[5m])
  / rate(mistralrs_speculative_draft_tokens_proposed_total[5m])

# Mean tokens accepted per verification step (1.0 = speculation is not helping)
1 + rate(mistralrs_speculative_draft_tokens_accepted_total[5m])
  / rate(mistralrs_speculative_drafts_total[5m])

# P99 time to first token, all models
histogram_quantile(0.99,
  sum(rate(mistralrs_time_to_first_token_seconds_bucket[5m])) by (le))

# P95 inter-token latency for one route/model
histogram_quantile(0.95,
  sum(rate(mistralrs_inter_token_latency_seconds_bucket{path="/v1/chat/completions"}[5m])) by (le))

# KV cache pressure (sustained 1.0 with a growing waiting queue means preemptions are likely)
mistralrs_kv_cache_blocks_used / mistralrs_kv_cache_blocks_total

# Sequence capacity utilization (sustained 1.0 with a growing waiting queue means requests are queueing)
mistralrs_sequences_running / mistralrs_sequences_capacity
```

## TOML

The same options are available under `[server]`:

```toml
[server]
port = 1234
access_log_format = "json"
access_log_health = false
disable_access_log = false
disable_request_id_header = false
disable_metrics = false
```
