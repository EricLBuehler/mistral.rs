Grouped small-row GEMV experiment

Decision: retain as an external experiment; no production kernel adoption.

The CUDA unit reuses each Q4K gate/up or Q4_1 down fragment across two or four sorted assignments. GPU dispatch construction, regular Q8_1 input and F32-intermediate quantization, SiLU, output memset, weighted atomic aggregation and BF16 conversion are included in each complete FFN call. It preserves indexed GEMV arithmetic and K-lane/reduction order. Atomic aggregation can occur in a different order. Packed MMQ uses different activation quantization/rounding, so the independent GEMV and FP32 comparisons are recorded separately.

The original output-feature layout (gate/up two features per warp, down four) compiles with 55/48 registers for grouped width2, 56/72 for width4; all have zero stack/spill bytes. On five balanced B8xQ3 subsets (M24), width2 improves over the current default indexed GEMV in all samples: median paired speedup 1.282x eager and 1.308x graph. At M32/40/42/56, it roughly ties current masked MMQ, with eager median ratios 0.992/1.002/1.001/0.998. Width4 is slower.

One bounded follow-up doubles output features per warp to four/eight. Width2 then uses 53/48 registers with zero spills. It loses all five cases in each M32/40/42/56 group: eager median speedup ratios versus MMQ 0.939/0.927/0.933/0.918. M24 remains faster than default GEMV, but less than the original layout (1.207x median). No further layouts were tested.

Each ordinary run evaluates the same 25 cases: five native M42, five native M56, and five each of balanced per-sequence M24/M32/M40 subsets from native B8xQ7 captures. Correctness precedes timings. Both widths must match original GEMV under relative RMS <1e-3 and cosine >.999999; current default must match captured native outputs under the same guard. Graph replay is compared with eager output, including changed routing IDs in the same device allocation and restoration. Both runs pass. Separate post-timing FP32 oracles cover all25 outputs and remain consistent with indexed GEMV quantization error.

The two initial sanitizer attempts instrumented timing replays and were stopped near the intended bounded runtime; their logs/metadata remain as incomplete runs, not pass/fail evidence. Final sanitizer checks use a separate validation-only Rust harness with no warmups or timing loops, linked to the exact existing CUDA object for each layout. The filter selects all new grouped GEMV kernels. It covers both widths and changed-route graph execution; completed logs contain ERROR SUMMARY: 0 errors. These checker outputs are not performance measurements.

Limits: repeated single-layer weights can have different cache behavior from full-model execution. All inputs/routes are real saved captures or explicitly derived balanced subsets; no whole-model gain is claimed. The experiment does not measure DRAM traffic or establish a hardware bandwidth ceiling. Normal timing runs record whole-child GPU clock/power/temperature samples and process isolation, with editor indexer processes paused. The width2 M24 gain supports investigating the existing MMQ sub-32-row dispatch as a smaller production alternative; broader eligibility for a new GEMV kernel has not been validated.
