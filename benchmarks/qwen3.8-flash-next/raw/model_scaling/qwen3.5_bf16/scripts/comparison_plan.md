# BF16 engine comparison preparation

The comparison is gated on both `mistralrs_bf16/metadata.json` and `vllm_bf16/metadata.json` reporting complete, successful request subprocesses, clean owned-server/container cleanup, and unchanged source manifests. No partial-trial rates are used.

After both runs finish and root authorizes reporting, run `compare_bf16.py --native <completed-native-directory> --vllm <completed-vllm-directory>`. Explicit directories support retained startup attempts and retries; unsuccessful attempts never enter statistics. It validates all seven trials at each concurrency, including two excluded warmups, then recomputes means and sample standard deviations over the five measured trials. Aggregate output rate, latency-weighted per-active output rate, mean active requests, and mean request latency retain their raw trial samples. C6/C1, C8/C1, and mistral.rs/vLLM ratios divide arithmetic means; they are not paired causal effects or confidence intervals.

The request validator checks completion status, indices, exact bodies, prompt hashes and token counts, 128 output tokens, no reported cached tokens, and timing arithmetic. Cross-engine gates require matching model config/index, checkpoint path, frozen harnesses, tokenizer, and ordered requests. Output text agreement is recorded separately; identical greedy request settings do not guarantee identical continuations or expert routes.

Both engines use BF16 weights, BF16 attention KV, BF16 convolution state, and F32 GDN recurrent state. `precision_evidence.json` ties this to the checkpoint and hashed native/actual-container implementation sources. The recurrent precision statement comes from that source flow, not the attention-KV startup log. Comparison validation checks the native source manifest and immutable Docker image identity against this evidence.

Physical cache allocations differ: mistral.rs caps its cache to context; vLLM has an explicit 4 GiB budget. The summary retains both startup capacities and exact engine identities. Optional metrics include warmups and are engine-specific. Clock, temperature, and power ranges use exact whole-command UTC boundaries including warmups, since the frozen harness lacks absolute per-trial timestamps. GPU CSV local timestamps use the recorded host timezone file. Global swap-in/out deltas and process VmSwap endpoints remain separate; neither establishes GPU paging. vLLM process memory describes the container init process and can omit worker children. No missing metric is substituted with zero. The sequential runs are not randomized and do not establish Flash-Next or MTP performance.

`plan_comparison_archive.py` accepts the same selected run directories plus repeated `--failed-run` paths. It refuses incomplete selected runs, and records failed attempts separately without including their partial results in statistics. It prepares a file inventory with source hashes and hashes of any sanitized copies, without copying into the repository. Run it only after all GPU timing/profiling has stopped, since hashing excluded caches can read substantial data. Intended compact destination is a root-approved subtree beside `raw/model_scaling/current_profile`. Include requests/results, server and harness logs, lifecycle metadata, startup backend evidence, memory/clock snapshots, selected config/index files, exact scripts, and final summaries. Metadata credentials and recognizable token values are redacted while original hashes remain in provenance.

Exclude tokenizer copies, compiler/runtime caches, profiler traces, binaries, weights, and text files over 2 MiB. Excluded result-directory files receive external paths, sizes, and SHA256 hashes. Model shard inventories describe existing checkpoint paths/sizes/header checks without claiming newly computed full-weight hashes. Container image identity remains its immutable image digest. A final archive needs a new manifest covering copied bytes, an external-artifact inventory, and a brief scope README; original source manifests can reference deliberately omitted files.

All preparation is CPU-only. Unit fixtures exercise malformed/incomplete trials, wrong request settings, token counts, prefix reuse, arithmetic tampering, and secret redaction. No real comparison or archive plan is generated until both runs finish.
